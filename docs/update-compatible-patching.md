# Genesis 플러그인 업데이트 후 번역 재사용 (개발 중 / 미배포)

이 문서는 다음 버전용 **소스 수정**의 동작 범위를 기록합니다. GitHub에 공개된
`v0.2.4` 바이너리의 기능을 설명하는 문서가 아닙니다.

## 목적과 안전 기준

기존 배포판에서는 대상 ESM/STRINGS **파일 전체의 SHA-256이 정확히 일치할 때만**
번역을 적용했습니다. 다른 필드 하나가 추가되어도 적용이 차단됐습니다.

새 구현에서 `text_recipe` 작업은 다음 순서로 동작합니다.

1. 입력 해시가 공식 지원판/알려진 기존 한패와 같다면 **기존의 엄격한 적용 및
   고정 결과 해시 검사**를 사용합니다.
2. 입력 해시가 다르다면 파일을 안전하게 파싱한 뒤, 같은 `레코드 종류 + FormID
   + 필드 + 등장 순서`와 **동일한 영어 원문**이 있는 항목만 기존 번역으로
   바꿉니다. Strings에서는 `String ID + 영어 원문`을 사용합니다.
3. `upgrade_from`에 등록된 과거 한국어 원문도, **현재 공식 번역 목적문이 동일한
   경우에 한해** 번역 갱신용 입력으로 인정합니다.
4. 없거나 원문이 변경된 항목은 건너뜁니다. 번역이 하나도 적용되지 않으면
   해당 파일은 `no_matching_changes` 상태로 두며 덮어쓰지 않습니다.
5. 실제로 수정할 파일만 준비 폴더에 생성합니다. 생성된 파일의 해시를 **이번
   실행에서 재계산해** 적용·복원·임의 변경 검사의 기준으로 저장합니다.

오작동 방지를 위해 잘못된 파일 구조, 중복 번역 키, 해석할 수 없는 손상된
플러그인, 토큰/태그 누락 번역은 여전히 실패시킵니다. 폰트·HUD·기타
바이너리 패치의 **전체 해시 검사도 그대로 유지**합니다. MO2에 원본 모드가
비활성화됐거나 더 높은 우선순위 모드가 같은 파일을 제공한다면 해당
텍스트 레시피만 건너뛰고 나머지 작업은 진행합니다.

## 지원 및 한계

- 지원: 같은 이름/경로의 플러그인에 레코드가 추가됐거나, 일부 텍스트만
  수정됐거나, STRINGS에 ID가 추가·변경된 업데이트.
- 미지원: 플러그인명/모드 설치 경로 변경, 레코드 FormID의 전면 재배치,
  필드가 다른 구조로 변경된 경우. 이런 항목은 안전하게 재식별할 데이터가
  없으므로 **자동 추측해 강제 적용하지 않음**.
- 게임 본편·DLC의 검사 대상 해시가 바뀌면 **텍스트 레시피만 진행**하고
  폰트·HUD·복사·fallback 작업은 제외합니다. 게임/DLC의 실제 해시는
  준비 결과에 기록하며, 적용 전에 다시 바뀌었다면 중단합니다.
- 필수 게임/DLC 파일 자체가 없으면 실패합니다. 게임 실행 호환성을
  보장한다는 뜻은 아니므로 게임 업데이트에 대한 플레이 검증은 별도입니다.
- 패칭 위치는 기존 파일 그대로입니다. 작업 전 원본 백업을 만들고, 적용 직전
  파일이 바뀌었으면 중단하며, 복원은 이번 실행에 기록된 원본으로 되돌립니다.

## 검증

```powershell
python -m unittest test_patch_engine test_installer_backend test_patcher_app
```

합성 ESM/STRINGS 업데이트, 변경·삭제된 레코드 건너뛰기, 과거 한국어 입력
갱신, 실제 생성 해시, 적용·복원, 파일 무결성과 안전 오류를 검증합니다.
**8.8.5 이상 실제 Genesis 게임팩에서의 동작은 아직 검증하지 않았습니다.**
